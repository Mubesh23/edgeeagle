# Mobile foundation

Expo SDK 56, React Native, TypeScript, and Expo Router for iOS and Android.
The single native-stack route shows offline foundation content. It makes no API
or provider calls and contains no domain calculations, auth, persistence, trading,
or placeholder product tabs. The generated API client and TanStack Query will be
added when there is a mobile data workflow to consume.

## Local development

From repository root:

```sh
scripts/bootstrap
corepack pnpm --filter @edgeeagle/mobile dev
```

This starts Expo Go mode on localhost.
The command selects IPv4-first localhost resolution to match Expo's advertised
127.0.0.1 bundle URLs on machines that otherwise bind localhost only on IPv6.
Use an SDK 56-compatible Expo Go client in a local simulator/emulator;
starting Metro alone does not test native rendering.
Physical-device access requires an explicitly chosen LAN setup instead of this
loopback default. No Expo account, EAS project, signing credentials, API server,
or cloud deployment is needed for the routine checks.

SDK 56 matches the existing Node 20.20.1 development environment; the root Node
engine range now follows React Native 0.85's supported versions. SDK 57 requires
Node 22.13+. Mobile pins Expo's matching React 19.2.3/native packages and
TypeScript 6.0.3; web remains independently pinned. React DOM and animation peers
are included to satisfy the Router/native dependency graph, not to add a second
web application or custom animated UI.

## Validation and generated output

Root format/lint/typecheck/test/build/validate commands include mobile.
The package test uses jest-expo and React Native Testing Library, native test
mocks, and a rejecting fetch spy. It checks visible capability limits and no
network requests. It is not a simulator or device test.

`scripts/build` runs offline Expo exports for iOS and Android to ignored
`apps/mobile/dist/` (bundles, assets, metadata), generated from app/, src/,
app.json, and the locked dependency graph. This proves Metro/Hermes bundling,
not native compilation, signing, installation, or device operation.
`apps/mobile/.expo/` is ignored local Expo state, regenerated by Expo start/export.

Optional dependency verification (public Expo metadata, separate from offline
routine validation):

```sh
EXPO_NO_TELEMETRY=1 corepack pnpm --filter @edgeeagle/mobile exec expo install --check
```

Before a release, verify Expo Go on both platforms, screen readers, increased
font sizes, landscape/safe areas, and actual-device performance. Native projects,
EAS configuration, store IDs, push permissions, and production security are
intentionally absent.

The shell uses native stack headers, system fonts with default font scaling,
selectable text, and a ScrollView with safe-area padding. Its fixed dark palette
follows the PRD's analytical presentation; system color themes remain later work.
